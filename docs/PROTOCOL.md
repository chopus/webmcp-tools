# Bridge Protocol v1 — contract between `server/` and `extension/`

This document is the **authoritative contract**. The MCP server (`server/`) and the
Chrome extension (`extension/`) are developed independently and must both implement it
exactly.

## Hops

```
MCP client ⟷ (stdio, JSON-RPC) ⟷ MCP server/hub ⟷ (TCP 127.0.0.1, NDJSON) ⟷ native relay
                ⟷ (native messaging: 4-byte little-endian length-prefixed UTF-8 JSON on stdio) ⟷ extension SW
```

The **relay is transparent**: it forwards identical JSON payloads between the TCP socket
(newline-delimited) and the native-messaging stdio frames. Only hub and extension
produce/consume messages.

## Envelope

Every message is a single JSON object, one per TCP line / native frame:

```ts
// hub → extension
{ "v": 1, "kind": "request",  "id": 42, "tool": "navigate", "params": { … } }

// extension → hub (success)
{ "v": 1, "kind": "response", "id": 42, "ok": true, "result": { … } }

// extension → hub (failure)
{ "v": 1, "kind": "response", "id": 42, "ok": false,
  "error": { "message": "human-readable", "code": "ETAB_NOT_FOUND" } }

// extension → hub (async notification)
{ "v": 1, "kind": "event", "event": "extensionHello", "data": { … } }
```

- `id` is a monotonically increasing integer generated by the hub; the extension copies
  it verbatim into the response. Only one in-flight request per `id`.
- `code` is a short machine string: `ETAB_NOT_FOUND | ENO_SUCH_REF | ENO_SUCH_SELECTOR |
  ETIMEOUT | EEXECUTION | EDEBUGGER | EWEBMCP | EARGS | ENAVIGATION`.
- Errors: never throw without responding; every request gets exactly one response.

## Handshake / discovery

1. The hub binds `127.0.0.1` on an ephemeral port and writes
   `os.tmpdir()/webmcp-tools-hub.json` → `{ "port": 0, "token": "<random hex>" }`.
   (Owner-only permissions; removed on shutdown.)
2. The relay reads that file, connects, then immediately sends:
   `{ "v":1, "kind":"hello", "who":"relay", "token":"<hex>" }`.
   An invalid/missing token → hub closes the socket. Valid → hub replies
   `{ "v":1, "kind":"hello", "who":"hub" }`.
3. The extension (having spawned the relay via `chrome.runtime.connectNative`) then sends:
   `{ "v":1, "kind":"event", "event":"extensionHello",
      "data": { "instanceId":"<uuid>", "extensionVersion":"…", "chromeVersion":"…", "userAgent":"…", "platform":"…" } }`
   (if this event is missing, the hub's first tool call still works; the event is
   informational and also re-sent on every (re)connect).

**Multiple browsers.** `instanceId` is a UUID the extension stores in
`chrome.storage.local` — stable per browser profile, different for each browser.
The hub keeps one connection per `instanceId`:

- Same `instanceId` from a new socket ⇒ the extension reconnected; the stale
  socket is dropped.
- Different `instanceId`s coexist (e.g. the user's daily Chrome and a test
  Chrome). Tool calls without an explicit `instanceId` target the **most
  recently connected** instance; every MCP tool also accepts an optional
  `instanceId` parameter to pin a browser, and `get_browser_info` returns
  `{ …, instanceId, instances: [{ instanceId, … }] }`.

The extension keeps the native port open (keeps the MV3 service worker alive) and
reconnects with backoff (1s, 2s, 5s, 10s… max 30s) if the relay/server dies.

## Tool matrix

`params` are the exact object the extension receives. Every param below is required
unless marked `?`. The MCP layer (server) owns zod validation; the extension may assume
shapes are valid but **must** still fail gracefully with `EARGS` if a required param is
missing.

### Common conventions

- **Tab resolution:** any `tabId?` that is omitted/null → the **active tab of the
  last-focused window**. The extension resolves it once per request.
- **Targeting:** interaction tools accept `ref?` (int, from `snapshot`) or `selector?`
  (CSS). Exactly one must be provided at the MCP layer; the extension resolves `ref`
  first. `ref` is only valid until the tab navigates (registry reset on commit).
- **`timeoutMs`** caps the whole operation server-side (default per tool) — the
  extension should also internally time out and answer `ETIMEOUT`.

### `Tab` object (returned by tab tools)

```ts
{ tabId: number, windowId: number, index: number, title: string, url: string,
  active: boolean, pinned: boolean, status: "loading"|"complete",
  favIconUrl?: string, audible?: boolean }
```

### 1. Browser / tabs

| tool | params | result |
|---|---|---|
| `get_browser_info` | `{}` | `{ chromeVersion, userAgent, platform, extensionVersion }` |
| `list_tabs` | `{}` | `{ tabs: Tab[] }` (current window group: all windows) |
| `new_tab` | `{ url?="about:blank", active?=true, windowId? }` | `{ tab: Tab }` |
| `activate_tab` | `{ tabId }` | `{ tab: Tab }` (also focuses its window) |
| `close_tab` | `{ tabId }` | `{ closed: true }` |

### 2. Navigation

| tool | params | result |
|---|---|---|
| `navigate` | `{ tabId?, url, timeoutMs?=30000 }` | `{ tabId, url, title }` — resolves when `status === "complete"` or timeout (timeout → `ETIMEOUT`) |
| `go_back` / `go_forward` | `{ tabId?, timeoutMs?=15000 }` | `{ tabId, url, title }` (no history → `{ url, title, navigated: false }`) |
| `reload` | `{ tabId?, bypassCache?=false, timeoutMs?=30000 }` | `{ tabId, url, title }` |
| `wait_for` | `{ tabId?, text?, selector?, timeoutMs?=10000 }` | `{ found: boolean, matched: "text"\|"selector"\|"none", tabId, url, title }` — polls ~250ms; exactly one of `text`/`selector` |

### 3. Observation

| tool | params | result |
|---|---|---|
| `snapshot` | `{ tabId?, maxElements?=800, viewportOnly?=false }` | see below |
| `get_page_text` | `{ tabId?, maxChars?=20000 }` | `{ tabId, url, title, text, truncated: boolean }` — `innerText` of `document.body` |
| `get_links` | `{ tabId? }` | `{ links: [{ text, href, internal: boolean }] }` — first 300 anchors with href |
| `screenshot` | `{ tabId?, format?="png"\|"jpeg", quality?=80, fullPage?=false, maxWidth?=1600 }` | `{ format, width, height, dataBase64 }` — downscale to `maxWidth` if wider; keep total base64 < ~6MB by lowering quality/resolution |

`snapshot` result:

```ts
{ tabId, url, title,
  viewport: { scrollX, scrollY, width, height },
  elements: [{
    ref: number,            // positive int, stable until navigation
    tag: string,            // lowercase tagName
    role?: string,          // explicit role or inferred ARIA role
    text?: string,          // innerText, max 120 chars, trimmed
    ariaLabel?: string, value?: string, placeholder?: string, checked?: boolean,
    href?: string, name?: string, id?: string,
    rect: { x, y, w, h },   // viewport-relative CSS px
    visible: boolean,
    options?: string[]      // <select> option labels (≤30)
  }],
  truncated: boolean }
```

Snapshot collects **interactive** elements: `a, button, input, select, textarea,
summary, [onclick], [contenteditable], [role]` — visible (non-zero box, not
`visibility:hidden`/`display:none`), deduped, ordered by document position. `truncated`
is true when `maxElements` cut the list.

### 4. Interaction

| tool | params | result |
|---|---|---|
| `click` | `{ tabId?, ref?, selector?, button?="left"\|"right"\|"middle", clickCount?=1, modifiers?=[], trusted?=false, timeoutMs?=5000 }` | `{ clicked: true, tag, text? }` |
| `type_text` | `{ tabId?, ref?, selector?, text, clearFirst?=true, submit?=false, trusted?=false, timeoutMs?=10000 }` | `{ typed: true }` — `submit` presses Enter after typing |
| `press_key` | `{ tabId?, key, ref?, selector?, trusted?=false, timeoutMs?=5000 }` | `{ pressed: true }` — `key` like `Enter\|Tab\|Escape\|ArrowDown\|Backspace\|a\|Control+A` |
| `hover` | `{ tabId?, ref?, selector?, timeoutMs?=5000 }` | `{ hovered: true }` |
| `scroll` | `{ tabId?, direction?="up"\|"down"\|"left"\|"right", amount?=600, ref?, selector?, smooth?=true }` | `{ scrollX, scrollY }` — targets element if given else page |
| `select_option` | `{ tabId?, ref?, selector?, value?, label?, index?, timeoutMs?=5000 }` | `{ selected: string[] }` — exactly one of value/label/index; fires `input`+`change` |
| `drag` | `{ tabId?, fromRef?, fromSelector?, toRef?, toSelector?, trusted?=false, timeoutMs?=8000 }` | `{ dragged: true }` |

Trusted mode (`trusted: true`): use `chrome.debugger` + CDP `Input.dispatchMouseEvent`
(`/Input.dispatchKeyEvent`, `/Input.insertText`) with element-center coordinates from
the content script; attach → act → detach. Non-trusted: content-script synthetic events
(pointer/mouse/keyboard sequences that respect React/Vue expectations).

### 5. JavaScript

| tool | params | result |
|---|---|---|
| `evaluate` | `{ tabId?, function: "(args) => expression-or-promise", args?={}, world?="MAIN"\|"ISOLATED", awaitPromise?=true, timeoutMs?=10000 }` | `{ result: null\|value, exception?: string }` — JSON-serializable returns only; non-serializable → `{ result: null, exception: "non-serializable result" }` |

### 6. Console / network

| tool | params | result |
|---|---|---|
| `get_console_logs` | `{ tabId?, levels?=["error","warn","log","info","debug"], lastN?=200 }` | `{ logs: [{ ts, tabId, level, text }] }` — ring buffer 1000/tab in the SW, cleared on navigation |
| `get_network_requests` | `{ tabId?, urlContains?, lastN?=50 }` | `{ requests: [{ ts, method, url, status, type }] }` — attaches `chrome.debugger`, `Network.enable`, ring buffer 500/tab |
| `stop_network_capture` | `{ tabId? }` | `{ stopped: true }` — detaches debugger for that tab (if attached only for capture) |

### 7. WebMCP

| tool | params | result |
|---|---|---|
| `list_webmcp_tools` | `{ tabId?, injectPolyfill?=false }` | `{ supported: boolean, mode: "native"\|"polyfill"\|"declarative"\|"none", tools: [{ name, title?, description?, inputSchema?, origin?, annotations? }] }` |
| `call_webmcp_tool` | `{ tabId?, name, args?={}, timeoutMs?=30000 }` | `{ ok: true, result }` or response-level error `{ ok:false, error:{ message, code:"EWEBMCP" } }` |

Semantics (all page evaluation happens in the **MAIN world** via
`chrome.scripting.executeScript({ world: "MAIN" })`):

- `supported` = `!!document.modelContext` (native Chrome ≥149 / origin trial, or the
  page already ran the polyfill which defines the same property).
- If `injectPolyfill` and not supported → inject the vendored polyfill
  (`extension/lib/webmcp-polyfill.js` source as MAIN-world script), then re-check.
- Discovery order: `await document.modelContext.getTools()` when available; else read
  `window.__webmcp_registered_tools` (Map values) and declarative `form[toolname]`
  elements. `mode` reflects the source (`native` if `document.modelContext` was not
  defined by a polyfill — best effort, `polyfill` if `window.__webmcp_registered_tools`
  exists, `declarative` if only `form[toolname]` forms, `none` otherwise).
- Execution: prefer `await document.modelContext.executeTool(tool, args)`; fallback to
  polyfilled execution for declarative forms (set values, fire `submit`). Tool lookup by
  `name`. JSON-serialize results; async results awaited.

## Server-side MCP behavior

- Tool names/params are exposed 1:1 under the same names (camelCase→snake_case already
  applied above). Responses to the MCP client: `{type:"text", text: prettyJSON}` for all
  tools except `screenshot` → `{type:"image", data, mimeType}` and `snapshot` → text
  listing `[ref] tag "text" (role, value…)` one per line plus a JSON appendix.
- If the extension is not connected when a tool is called → MCP error
  `extension_not_connected` with instructions to load the extension + install the host.
- Per-request hub timeout: `timeoutMs` (cap 120000). Timeouts surface as MCP tool errors.
